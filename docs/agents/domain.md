# 领域文档

工程技能在探索代码库时应如何读取本仓库的领域文档。

## 探索前必读

- 仓库根目录的 **`CONTEXT.md`**，或
- 如果存在 **`CONTEXT-MAP.md`**：它会指向每个上下文各自的 `CONTEXT.md`，读取与当前主题相关的部分
- **`docs/adr/`**：阅读与当前工作区域相关的 ADR

以上文件若不存在，**静默跳过**。不要提示文件缺失，也不要主动建议创建。这些文件由 `/domain-modeling` 技能在实际解析术语或决策时懒创建。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用词汇表中的术语

在输出内容（Issue 标题、重构提案、假设、测试名称）中命名领域概念时，使用 `CONTEXT.md` 中定义的术语，不要偏移到词汇表明确排除的同义词。

如果需要的概念尚未在词汇表中，这是一个信号：要么你在使用项目不存在的语言（重新考虑），要么存在真实缺口（记录给 `/domain-modeling`）。

## 标记 ADR 冲突

如果输出内容与现有 ADR 矛盾，显式标出而非静默覆盖：

> _与 ADR-0001（xxx）冲突，但值得重新讨论，因为……_
